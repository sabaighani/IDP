# Architecture Decision Records

Short documents that record a significant technical decision and the reasoning behind it.

**Format** (one file per decision, numbered in order, e.g. `0002-use-taskfile.md`)
- **Status**: Proposed, Accepted, or Superseded
- **Context**: what problem or force led to the decision
- **Decision**: what was chosen
- **Consequences**: what gets easier and what gets harder

**Rules**
- Never rewrite an accepted ADR. If the decision changes, add a new ADR that supersedes it.
- Keep each one short. A few paragraphs is enough.
